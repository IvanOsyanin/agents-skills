# Редактируемый результат и проверка

Сохраняй запрошенные пользователем форматы. Если формат не задан, практичный
комплект — редактируемый Draw.io и SVG для просмотра; PNG полезен для вставки
в документы. Не генерируй схему как растр посредством ImageGen: здесь важны
точные подписи, связи и дальнейшее редактирование фигур.

Для проекта результатом по умолчанию являются одна итоговая информационная схема
и одна итоговая функциональная схема, согласованные между собой и покрывающие
подтверждённые сценарии в оговорённой области. Если пользователь запросил только
один вид — выдай только его. Несколько листов/страниц допустимы как части одной
схемы; не выдавай отдельные файлы-альтернативы для каждого сценария, подсистемы
или варианта. Заверши построение и проверки до финального ответа: не останавливайся
на черновике/эскизе, если пользователь явно не просил именно черновик или нет
блокирующего пробела, который нельзя безопасно обозначить как неизвестный.

Если пользователь передал готовую архитектурную схему, обработай её как исходный
контекст и базу итоговой информационной схемы, а не только как образец стиля.
Сохрани подтверждённые компоненты, границы, связи и ID/номера; проверь и уточни их
по доступным источникам. Построй функциональную схему на основе уточнённой модели
самостоятельно — не требуй от пользователя повторно описать её текстом. При
неоднозначностях, не блокирующих работу, отметь допущения; задай вопрос только если
без ответа невозможно корректно выбрать область или смысл модели. Не изменяй
пользовательский исходник разрушительно.

Файл [notation.drawio](../assets/notation.drawio) содержит редактируемые примитивы,
а [notation.svg](../assets/notation.svg) — их визуальное представление. Это образец
фигур, не универсальная раскладка сценария. Копируй подходящие фигуры; масштаб,
дорожки и число листов выбирай по содержанию.
Согласованный учебный пример — [example-pair.drawio](../assets/example-pair.drawio)
и [его SVG](../assets/example-pair.svg). Он показывает один успешный сценарий,
точные имена функций, два направления данных с кружками у поставщиков и единые
номера интерфейсов в обоих представлениях; не задаёт состав нового проекта.
Assets используют основной профиль новых образцов. Для точного сохранения старого
оформления выбери альтернативный профиль явно, а не смешивай фигуры случайно.

Если используешь генератор, держи одну модель текста и геометрии для всех форматов.
Не исправляй лишь PNG, оставляя иной Draw.io. Основному профилю объекта данных
подходит `shape=note`: складка в новых образцах видима. Лишь для прежнего профиля
без складки нужен иной контур, например XML stencil; формат описан в
[официальной документации Draw.io](https://github.com/jgraph/drawio/wiki/Shapes-and-Stencils).

Учебные assets воспроизводятся из единой модели текста/геометрии скриптом
`python scripts/build_assets.py` (Python 3, только стандартная библиотека).
Он обновляет Draw.io/SVG и удаляет устаревшие PNG при изменении SVG. PNG можно
получить опцией `--browser <путь к Chromium/Edge>`; это рендер SVG, не Draw.io.
Проверка структуры и согласованности примера: `python scripts/build_assets.py --check`.
Скрипт — генератор учебных ресурсов, не обязательный генератор пользовательских схем.

Минимальная проверка:

- XML открывается; ID уникальны; source/target/parent существуют.
- Фигуры и текст помещаются в область страницы и родительский контейнер.
- Стрелки соединены с нужными гранями, не проходят через посторонний блок/подпись.
- Условия относятся к видимой ветви; возврат и независимый запуск не потеряны.
- ID и полные имена компонентов, точные имена функций и номера интерфейсов
  согласованы между представлениями; входные данные,
  результат и режим обмена не противоречат реестру оснований.
- Шрифт читается на обычном масштабе листа; большие схемы имеют отдельные листы.
- Одна функция/сущность на фигуру; у транзитного компонента нет выдуманного владения.
- Информационные стрелки идут по данным, кружки стоят у поставщика; синхронность
  не закодирована цветом. Технические ACK и протоколы не загромождают обзорный лист.
- Функциональные цилиндры и объекты со складкой не перепутаны, их связи пунктирные;
  голубые действия и зелёные/розовые события относятся к одному выбранному профилю.
- PNG/SVG визуально просмотрены целиком и по фрагментам. Если доступен редактор,
  проверь также Draw.io в нём; иначе честно обозначь ограничение проверки.

Проверка геометрии не доказывает корректность бизнес-смысла, а синтаксическая
проверка Draw.io — совпадение его реального рендера с SVG. Не записывай в отчёт
жёстко заданные числа «проверенных» узлов: считай их из созданной модели.

Используй переносимые пути относительно каталога скилла. `agents/openai.yaml`
содержит метаданные интерфейса Codex; инструкция и ресурсы не требуют его API
или конкретного инструмента генерации. В другой среде следуй тому же SKILL.md.
Не выдавай Draw.io за подтверждённый формат импорта WebOTAR.
